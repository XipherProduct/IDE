Ты senior frontend/full-stack engineer. Работаешь внутри существующего репозитория `alaska-ai`. Твоя задача: реализовать MVP личного кабинета для AI-сервиса на Next.js, аккуратно встроив его в текущий проект, а не делая абстрактный дашборд с нуля.

Сначала изучи текущий код, потом внеси изменения. Не пиши длинную теорию. Сначала дай короткий план, затем сразу реализуй код, затем покажи список измененных файлов и результаты проверки.

Контекст проекта, который уже подтвержден:

- Это Next.js 15.5.15 + React 19.1 + TypeScript проект.
- Используется App Router.
- Используется `next-intl` с локалями `ru` и `en`, locale prefix всегда включен.
- Основной layout находится в `src/app/[locale]/layout.tsx`.
- Глобальные стили и токены темы находятся в `src/app/globals.css`.
- В проекте уже есть дизайн-система в Arctic-стиле: тёмные ink/ice/glacier токены, aurora backdrop, glass/frost атмосфера.
- Уже есть готовые UI primitives: `Button`, `Card`, `Tabs`, `Dialog`, `Tooltip`, `Badge`.
- Уже есть `Header`, `Footer`, `Container`.
- Уже есть продуктовый контекст Alaska AI / Alaska CLI: 75+ моделей, 7 провайдеров, CLI-first продукт, hosted-тарифы только планируются.
- Список AI-провайдеров уже есть в `src/lib/providers.ts`.
- В проекте сейчас нет настоящего backend layer для ЛК, нет auth, нет БД, нет API routes под личный кабинет.

Главная цель:

Сделай качественный, визуально сильный и реалистичный MVP личного кабинета, который выглядит как естественное продолжение текущего сайта Alaska AI. Это должен быть не “generic admin panel”, а “control center” для пользователя AI-сервиса в фирменной Arctic-стилистике проекта.

Что нужно сделать:

1. Добавить новый локализованный раздел личного кабинета.
- Предпочтительный маршрут: `src/app/[locale]/account/page.tsx`.
- Если сочтешь уместным, добавь локализованный pathname в `src/i18n/routing.ts`, например `ru: "/kabinet", en: "/account"`.
- Добавь вход в ЛК из хедера, но не ломай текущую навигацию маркетингового сайта.

2. Реализовать MVP ЛК с минимальным, но живым функционалом.
- Экран Overview:
  - приветствие пользователя;
  - карточка текущего плана;
  - короткая usage-статистика;
  - статус подключенных провайдеров;
  - последние сессии/активность;
  - быстрые действия.
- Экран Providers / Keys:
  - показать список провайдеров на основе `src/lib/providers.ts`;
  - дать возможность “подключить/отключить” провайдера в UI;
  - показывать маску ключа и статус подключения;
  - не хранить реальные секреты в коде, в логах и в открытом виде.
- Экран Sessions:
  - список последних AI-сессий/диалогов;
  - модель, провайдер, дата обновления, короткий статус;
  - закрепление/снятие закрепления;
  - открытие деталей в диалоге.
- Экран Preferences:
  - имя пользователя;
  - email-заглушка;
  - default model;
  - UI preference/тема/локальные настройки;
  - сохранение состояния.

3. Сделать функционал “минимальным, но рабочим”.
- Так как настоящего backend/auth нет, реализуй frontend MVP на mock-данных.
- Используй локальное состояние + `localStorage` для сохранения изменений между перезагрузками.
- Сделай это честно и прозрачно: не имитируй production-auth, не притворяйся, что есть сервер.
- Можно сделать `mock account store` в `src/lib/account/*`.
- Важно: raw API key не должен сохраняться как есть. Разрешено хранить только безопасную демонстрационную форму, например masked value / last4 / synthetic token label.

4. Визуально выдержать текущий стиль проекта.
- Переиспользуй существующие токены из `globals.css`.
- Переиспользуй существующие primitives, не тащи новую UI-библиотеку.
- Не делай банальный белый SaaS-дэшборд.
- Используй текущую арктическую эстетику: glow, frost, aurora, темные панели, четкие акценты.
- Интерфейс должен хорошо выглядеть и на desktop, и на mobile.

5. Сохранить архитектуру проекта.
- Не ломай существующие маркетинговые страницы.
- Не трогай лишние файлы.
- Новые компоненты разложи аккуратно, например в `src/components/account/*`.
- Новую локальную бизнес-логику/моки/типы вынеси в `src/lib/account/*`, если это реально улучшает читаемость.
- Не дроби структуру без необходимости.

6. Полностью локализовать новый раздел.
- Добавь все новые строки в `messages/ru.json` и `messages/en.json`.
- Не оставляй hardcoded UI text там, где уже используется `next-intl`.

7. Не переусложнять.
- Не добавляй `next-auth`, `supabase`, `prisma`, `zustand`, Redux и прочий тяжелый стек.
- Не добавляй новые зависимости без крайней необходимости.
- Не строй “будущий enterprise backend”.
- Это должен быть аккуратный MVP-слой внутри уже существующего сайта.

Технические требования:

- Используй TypeScript строго в стиле текущего проекта.
- Следуй текущему App Router подходу.
- Серверные и клиентские компоненты разделяй осмысленно.
- Для интерактивных частей используй client components.
- Если нужны комментарии в коде, делай их краткими и на русском.

- Не дублируй существующие стили и primitives, если их можно переиспользовать.
